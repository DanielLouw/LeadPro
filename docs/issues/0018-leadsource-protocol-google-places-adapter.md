# 0018 — Apify Lead Sources: LeadSource Protocol + Google Places Adapter Refactor

## What to build

Introduce the `LeadSource` Protocol and adapter registry that the entire multi-source pipeline is built on. Wrap the existing Google Places scraper in the first adapter. Refactor `execute_run()` to dispatch via the registry. No new sources are added in this slice — the goal is a clean protocol in place with Google Places running through it, all existing tests passing.

**LeadSource Protocol:**
Define a `LeadSource` Python Protocol with a single async method that accepts a `source_config` dict and `max_results` integer and returns `list[RawBusiness]`. This is the contract every adapter must satisfy.

**Adapter registry:**
A dict mapping source key strings (`'google_places'`, `'apify_google_maps'`, `'apify_facebook_pages'`) to their adapter instances. The pipeline looks up the adapter by `run.source` at execution time.

**GooglePlacesAdapter:**
Wraps the existing `scrape_queries()` function. Reads `queries` from `source_config` (and falls back to top-level `queries` in `config_yaml` for legacy runs without a `source_config` block). Populates `RawBusiness.external_id` from the Google `placeId`.

**Pipeline refactor (`execute_run()`):**
- Reads `run.source` from the DB row to select the adapter
- Reads shared YAML keys (`max_results_per_run`) and passes `source_config` block to the adapter
- Calculates `cost_usd` at run completion using the Google Places rate and writes it to `run.cost_usd`
- Handles legacy configs (no `source_config` block, top-level `queries`) transparently

**New YAML shape (generated by Config Builder going forward):**
```yaml
source: google_places
max_results_per_run: 10
source_config:
  queries:
    - plumbers in Austin TX
    - plumbers in Dallas TX
```

Legacy configs without `source_config` continue to work via the fallback path.

## Acceptance criteria

- [ ] `LeadSource` Protocol is defined and documented
- [ ] Adapter registry exists with `google_places` registered
- [ ] `execute_run()` dispatches to the adapter via the registry — no direct import of the Places scraper in the pipeline
- [ ] `GooglePlacesAdapter` passes `source_config.queries` (or legacy top-level `queries`) to the existing scraper
- [ ] `run.cost_usd` is written at completion for Google Places runs using the existing cost formula
- [ ] Legacy `config_yaml` (no `source_config` block) runs without error
- [ ] All existing tests pass without modification
- [ ] New unit tests: given a mocked `scrape_queries` response, `GooglePlacesAdapter.fetch()` returns correctly shaped `RawBusiness` records with `external_id` populated from `placeId`
